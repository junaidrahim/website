# Common Pitfalls of Documenting Software

- Write down philosophies around documenting code well
- Docs for Developers
- g3doc and developer friendliness
- Bundling docs with code, doc review and code review culture.

---

It's one of those boring problems that I am so interested in. Maybe it's because of my general interest in note taking and information hierarchies. Documenting software is hard, very few teams in the world manage to get it right. It's definitely never a problem that startups take seriously.

But I do, I deeply believe that writing good docs is a very high leverage activity and can get your team moving a lot faster if done properly.

Documentarians love structure.

- Main lessons
  - Bundling Docs with Code
  - Write for Skimming
  - Write Less
  - Writing without a Reading Culture
  - Feedback cycles
  - Docs need Review, Docs need Feedback
